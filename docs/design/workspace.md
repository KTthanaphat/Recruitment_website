# Workspace visual contract

Use [Foundations](foundations.md), [Home](home.md), and [Candidate Detail](candidate-detail.md) for existing type, color, control, and identity patterns. This contract covers presentation and navigation within Workspace; it does not change hiring eligibility, stage rules, permissions, persisted data, or public routes. Product behavior is in [Website Structure](../WEBSITE_STRUCTURE.md#routes-and-navigation).

## Intent and scope

Make one selected sourcing group faster to scan, with an obvious next action. Cover the Groups picker, selected-group header, five tabs, and their Overview, Sourcing, Pipeline, Offer, and Activity content. The canonical Workspace URL uses group `type` and `id`, `section`, `lang`, `site`, `pic`, and `sourcingWeek`; old `doc` and requisition Workspace links are compatibility inputs only. Reuse current source data and actions. Use flat surfaces, clear type hierarchy, restrained semantic tags, divided records, and visible keyboard focus.

## Picker at `/workspace`

- Show **Groups** only. Default to **Ongoing**; **All groups** includes every authorized group with a visible linked requisition, including filled and cancelled history. Unlinked groups stay out. Preserve the scope when returning from a group, and select All after opening a historical group URL. Place the compact scope toggle immediately before the role-gated New menu in the picker title area; on phones, keep them together on one row below the title with 44px targets. The menu opens the existing New Requisition or New Group creation flow.
- Place search, a live result count, and a compact **Sort by** control above the results. Search must still use the existing visible record fields and scope rules. Search and sort apply to all eligible matches, not just an initial slice. Empty and invalid-target states explain what happened and retain the controls.
- Use compact, horizontally divided rows. Give Group name a narrower, roughly 11rem minimum desktop column and tighter row padding; keep its name on one truncated line with Group ID below. Center the name/ID stack vertically against the row's other values while keeping the name's 44px target. The name opens that case with a visible hover/focus state; put full names in the accessible name or tooltip when shortened. Show status/attention, site and owner, open demand, and candidate count in aligned columns from tablet width. On phones, use one labeled row per record without page-level horizontal overflow.
- **Needs attention** is the default sort: rank the group's least-ready open, unfilled requisition state from No coverage through Late-stage coverage, then open demand descending, localized group name, and stable Group ID. Provide **Name A–Z** and **Oldest first**; the latter uses the selected-week sourcing update's last saved date, missing first. Sort affects presentation only.
- Show every match. From tablet width, bound the result region to the available viewport and scroll inside it, with its count and controls remaining visible. On phones, let the page scroll normally. Do not reintroduce the 12-result cap.
- Show **Readiness**, **Filled / total demand**, **Active / total candidates**, site/owner, linked requisitions, and latest sourcing save. Readiness is the least-ready state across authorized open, unfilled links. Demand includes all authorized links, including filled and closed, and caps accepted offers at requested headcount per requisition. Candidate totals use unique group members and the selected-header active condition. Keep group identity primary and show a dash for absent values.
- The linked count is a localized preview trigger. Show every authorized linked requisition's position, ID, current status, and filled/headcount in a bounded list. Open on mouse hover, keyboard focus, or click/tap; each row opens the existing requisition detail window. Close on Escape or outside click, and allow pointer movement between trigger and popup without flicker. Portal positioning keeps it clear of the picker scroll clipping. Search includes all visible linked IDs, even filled or closed ones.
- Use the selected-group header's soft readiness tag in picker rows, with status text only. When no open, unfilled link remains, use Filled for entirely fulfilled groups, Cancelled for entirely cancelled groups, or neutral Closed for mixed terminal results. Place terminal groups after ongoing groups in the default sort. Historical group tabs retain record context and history while inapplicable write controls are hidden or disabled.

## Selected-case header and section navigation

- Use a Candidate Detail-like identity hierarchy: quiet case icon, prominent group position, secondary `{group_id} | {site} | {owner}` values without visible field names, group readiness/SLA tags, and flat utility actions. Give each value an accessible localized label. Wrap long values; show `—` for a missing site and localized Unassigned for a missing owner. Readiness is the least-ready existing state across open, unfilled linked requisitions, with affected/total count. SLA shows the oldest such requisition's restart-aware age and limit, or the existing unknown fallback.
- In the expanded group header, vertically center the compact back arrow and Workspace breadcrumb by omitting the breadcrumb's bottom margin in this context only; keep a 44px phone target. Tighten padding, gaps, case-icon size, and unnecessary metric minimum heights. From 1080px, place the identity at left and four live metrics at right; from 1024px through 1079px, put metrics below the identity. Each lightly divided metric reads name, light-weight helper subtitle, then prominent value; phones use two columns. Long English and Thai values wrap without horizontal page overflow. Use a restrained white-to-pale-blue treatment without a static illustration.
- For a selected group, replace Open Sourcing and More with a labeled back arrow before Workspace. The arrow returns to the scoped Groups picker, retaining language, site, owner, and sourcing week. Expose it on phones; the five tabs own section navigation.
- On desktop (`lg` and wider), retain the 80px sticky collapse to group title and ID. Hide breadcrumbs, site/owner, tags, and metrics in that state; keep the tabs clear. Phones and tablets stay expanded and nonsticky on scroll.
- Keep **Overview, Sourcing, Pipeline, Offer, Activity** and their current `section` URL values. Put the tab strip and active panel in one bordered white Workspace box with a hairline separator below the tabs. At narrow widths, only the tab strip scrolls horizontally. Support Tab focus plus Arrow Left/Right and Home/End navigation. Preserve back/forward and refresh; replace old group `doc` scope with aggregate group scope and retain legacy `section=outcome` replacement.

## Overview

- Place **Hiring journey** and **Data quality** in two balanced panels from `lg`; stack journey first below that width. The journey's highlighted step is the Next action: first attention, otherwise current, otherwise next not-started. Its row opens the existing section. The Requisition step lists every visible linked requisition as a separate control opening its detail window, where role-gated Edit and Change Status remain. Shorten long positions to 30 characters plus an ellipsis, then show a valid `(L#)` suffix outside the truncating span so it remains visible; keep the full title accessible and ID/status beneath. Aggregate requisition-dependent completion requires every relevant linked requisition. Show an up-to-date message if no step remains.
- Present all seven journey steps as a numbered vertical rail with icon, label, detail, and text status. From 1024px, both Overview cards have the same 28rem height; journey and issue lists scroll within their respective cards while headings, overdue context, and eligible Edit/Change Status stay outside. Below 1024px, both cards grow naturally and their complete lists follow page scroll. Preserve step states, section destinations, keyboard focus, and phone touch targets.
- Put step detail beneath its title inside the step button and its status at the button's top right. Keep linked requisition controls separate from that button. Title the quality panel **Data quality**; make warning rows visually quiet while retaining all issue text, severity, actions, and overdue context.
- Show every data-quality issue in blocking/warning/info order, stable within severity; there is no top-three disclosure. Use one soft danger `{count} overdue` tag for overdue open linked requisitions, retaining each issue's existing action and role gate and the empty state. Use flat divided rows with a scoped circular severity icon. In Workspace only, render specific bilingual issue titles, explanations and action labels from stable internal issue codes and observed record context; do not expose duplicate-matching values, change detection or alter other shared issue-card callers.

## Sourcing, Pipeline, Offer, Activity

- **Sourcing:** from 1024px, use a one-third bounded vertical list of every expected Saturday update from first linked approval through the current week, newest first, beside a two-thirds selected-week editor. Give the selected row an accent edge; label complete dates Recorded, saved dates with missing channel values Incomplete, and missing records **Update needed / ต้องอัปเดตข้อมูล**. Show the accurate Saturday–Friday period under each date. The date picker and list synchronize with `sourcingWeek`; confirm before discarding an unsaved draft. Below 1024px, stack the bounded list above the naturally scrolling editor. Keep Save, validation, blank-as-unrecorded behavior, group details, and role gates; Records > Sourcing retains its own layout.
- At 1080px and wider, show the summary as three equal-height, separate white cards with compact spacing and near 30% / 34% / 36% widths; stack them in the same order below that width without page overflow. Use navy 16px headings, restrained borders/shadows, and a focusable bilingual information tooltip per metric. Help opens on hover, focus, and tap and closes on Escape or outside click. First, center the saved cumulative applicant number independently of the plain bottom-aligned `(+N)` selected-week text or `(—)` when unavailable; do not imply week-over-week growth. Put a compact eight-week Applicant trend graph beneath it, sizing its plot to the full width of Weekly update completeness, with its lower-hierarchy label beneath the graph. Keep unknown gaps, recorded zero, pale fill, keyboard-focusable point tooltips, screen-reader week list, and light horizontal gridlines. Set the y-axis upper tick to the next multiple of ten at or above 110% of the highest visible weekly value, with midpoint and zero ticks; leave enough space above the plot to show the upper tick label fully; show only `0` for all-zero known values. Beneath the graph, use a separator and one Weekly update completeness line showing recorded/expected weeks and percent (`3/32 (9%)`) above the accessible progress bar. Do not restore a separate Weeks with update records box. Second, title the card **Channel distribution** and size the solid-color donut responsively to about half the available card width, capped at 240px, with the full nonzero channel legend to its right. Directly beneath the Channel distribution title, use a subtitle naming up to three highest channels and their combined count and share of saved applicants (for example, `Top 3 channels: JobBKK, Others and JobThai in total 65 of 82 applicants (79%).`); use configured order for ties and omit this sentence in no-data and zero states. Rank by saved cumulative count with configured order for ties; keep configured Others separate. Third, show six active pipeline stages from Phone Screening through Offer as compact horizontal stacked bars of distinct group candidates who entered each stage, with stronger absolute totals and light dashed row separators. Keep names on one line with full-name tooltips if localized labels exceed the column. Omit a separate stage legend; preserve each colored segment's channel/count tooltip and an accessible channel breakdown per stage, including Unknown. Include pending and failed stage entries, exclude superseded entries, and count each candidate once per stage. Use the selected week's Friday or Bangkok today, whichever is earlier, as the candidate and stage-entry cutoff. Candidate-channel segments may appear without saved applicant counts in the donut; the two measures have different sources. Use one fixed, cheerful platform-aligned palette across donut, the channel legend, stage bars, and editor dots. No complete updates and complete-zero totals keep distinct text states.
- Give the Select week and Sourcing update heading areas matching height on desktop. Head the editor with the selected date, its actual Saturday–Friday date range beneath, date picker, and existing Details action; retain weekday subtitles in date-list rows. Arrange enabled channels in three columns where space permits on wide desktop, two at intermediate widths, and one on phones. Use flat channel rows with spacing and a bottom divider instead of individual boxes. Within each row, vertically align its colored dot/name, numeric input, and parenthesized preceding-week difference; right-align the number inside its input. Put the small preceding-week count beneath the channel name. Show a channel's difference only when both counts are known. Compute an in-form total from valid draft counts only when all enabled channels have values, displaying its preceding-week change as `120 (+8)`, `120 (-3)`, `120 (0)`, or `120 (—)` when unknown. Present this draft total as an unboxed divided row. Place the status tag at the editor's upper right, immediately left of a labeled, focusable save icon button; remove the bottom Save record button. Draft inputs do not alter the saved summary before Save. Do not add Notes, date search, or a More actions menu from the visual reference.
- **Pipeline:** retain stage lanes, drag behavior, candidate actions, stage semantics, and New Candidate eligibility. Simplify the outer panel and section heading so the board is the focus. Keep any board overflow inside the board region; phone layout must remain usable without horizontal page overflow.
- **Offer:** retain New Offer eligibility, reconciliation messaging, offer status and follow-up actions, impact information, record links, and all permission gates. Render offers as aligned divided rows from tablet width with labeled values on phones. Keep a distinct action control when it performs work; the record name opens its existing context.
- **Activity:** keep the existing newest-first history, record links, and current result limit. Show date/time, event, record/context, and status in divided rows on larger screens and labeled rows on phones. Preserve the full event text in accessible labels or tooltips when shortened.
- Add Actor to the Activity table using a sourcing updater or an unambiguous matching audit event. Show localized Unknown otherwise; do not substitute interviewer or owner. Bound desktop/tablet scrolling with the header in the same viewport.
- Render Activity status with the shared soft tag so the label has semantic-colored text on a light background.
