## Data access design

- Operational lists use `app_recruitment_list_v1` with server-side search, filters, sorting, and keyset cursors. Supported page sizes are 25, 50, and 100; the default is 50.
- Exact criteria counts use `app_recruitment_list_count_v1`, cached separately from pages. Page rows and cursor controls render without waiting for the count. Pending counts display as unknown; failed counts can be retried.
- Page and count caches are scoped by client instance and access identity, expire after 30 seconds, are bounded, and have entity-specific invalidation notifications.
- Candidate profiles, selected applications, requisitions, and groups hydrate through exact or bounded authorized reads. Candidate detail caches are client- and access-scope-bound for 30 seconds; selected-journey relations use 200-key chunks. Invitation and rejection templates load when their editors open. Selected-journey rejection drafts load only for the selected journey's stage instances. Candidate and group IDs are formatted for display only; stored values and callback keys remain raw.
- ID contract: newly generated candidate and position-group IDs use `CAN-00001` and `GRP-00001` minimum-width-five formatting while continuing their counters. Existing stored IDs and relationships, URLs, mutation keys, and exported source IDs remain raw and unchanged; `DGRP` formatting is unchanged. Shared display/search aliases pad CAN/GRP suffixes to at least five digits and never truncate six-digit or longer IDs. Unit and database boundary checks cover counters `1`, `9999`, `10000`, `99999`, and `100000` in `tests/unit/recruitment-id.test.cjs` and `tests/db/app-id-formatting.cjs`. The PGlite overlap/counter checks are serialized; they do not establish native cross-connection concurrency behavior.
- Home and report summaries use aggregate endpoints. Calendar Today data has its own date-bounded request. Complete report source ledgers are loaded only when exporting.
- The system-admin profile directory and recruiter assignment options read the complete profile projection through current-session verification and existing RLS only when the relevant editor/view opens. Cached results are client/profile/access-scope keyed; bootstrap remains self-profile only.
- Requisition lookups apply managed/unmatched/group/site criteria before page/count, preserve a selected projected row across search/page navigation, and clear that selection when its client, access scope, or eligibility filters change.
